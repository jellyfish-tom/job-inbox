# Job Inbox Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a private Next.js inbox that pulls matching remote FE jobs every 2h into Turso and lets you Apply/Reject plus note applied roles.

**Architecture:** One adapter per board normalizes listings to `NormalizedJob`. `refreshSource` filters, upserts, and writes events. Cookie auth on pages; bearer `REFRESH_SECRET` on `POST /api/refresh`. GitHub Actions matrix hits that route every 2h. UI never imports a source module.

**Tech Stack:** Next.js 16.2.6 App Router, React 19.2.4, TypeScript 5, Tailwind 4, Vitest 3, `@libsql/client`, Vercel Hobby, Turso, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-08-29-job-inbox-design.md`

```ts
export function normalizeUrl(url: string): string {
  const u = new URL(url);
  u.hash = "";
  u.search = "";
  u.hostname = u.hostname.toLowerCase();
  let path = u.pathname.replace(/\/+$/, "");
  if (path === "") path = "";
  return `${u.protocol}//${u.host}${path}`;
}
```

`applyJob` / `rejectJob` / `updateNotes`: update row + insert event (`user`) in one `db.batch` / explicit transaction. `applyJob` sets `appliedAt` to now only if `appliedAt` is null.

### Task 6: Refresh pipeline

**Tier:** T1  
**Files:**
- Create: `src/lib/refresh.ts`
- Test: `tests/refresh.test.ts`

**Interfaces:**
- Consumes: `getAdapter`, `isInstantReject`, `matchesCriteria`, all query functions
- Produces:

```ts
export type RefreshResult = {
  source: SourceId;
  runId: string;
  status: "ok" | "failed";
  fetched: number;
  inserted: number;
  skipped: number;
  rejected: number;
  error: string;
};

export async function refreshSource(source: SourceId): Promise<RefreshResult>;
```

Algorithm (this is the whole function):

1. `watermark = await getWatermark(source)`
2. `runId = await createRefreshRun(source, watermark)`
3. try:
   - `raws = await getAdapter(source).fetchListings()`
   - For each raw: `normalize` inside try; if throw, abort the whole run (`failed`, error `unparseable listing`, `rejected/inserted/skipped` as counted so far) — this is the “schema break, no half-parsed batch” rule when **normalize throws**. Counts: increment `fetched` for every raw; if normalize throws, fail the run immediately without upserting that item.
   - Build `FilterInput` from normalized fields: `description` and `location` parsed from `JSON.parse(rawJson)` best-effort (`description` / `locationRestrictions` join / `workplaceType`).
   - If `isInstantReject` or `!matchesCriteria` → `rejected++`, continue (no row).
   - If `postedAt` and watermark and `Date.parse(postedAt) <= Date.parse(watermark)` **and** you will only skip already-known: still call `upsertJob` (updated lastSeen). Spec: keep unknown ids OR postedAt > watermark. So: if existing path is “new id” AND postedAt <= watermark → `skipped++`, do not insert. If existing id → upsert (update). Implement `findJobId(source, externalId): Promise<string | null>` in `queries.ts` if needed.
   - Else `upsertJob`; `inserted++` on `inserted`, `skipped++` on `updated` or `deduped`.
   - `finishRefreshRun(..., { status: "ok", finishedAt: now, fetched, inserted, skipped, rejected, error: "" })`
4. catch: `finishRefreshRun(..., { status: "failed", finishedAt: now, error: String(err), ...counts })`
